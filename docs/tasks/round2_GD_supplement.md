## 1. 出力形式（取り込みで実際に問題になった点）

1. **YAML ブロックの中に脚注番号（[1] など）を入れないでください。** 前回は `"…だった。"[4][5]` のように YAML 内に脚注が入り、YAML として読めませんでした。文字列の内側に入った例（「DCI[30] 8,000」）もありました。出典の対応は provenance と、YAML の外の表で示してください。
2. **アンカー（&）とマージキー（<<:）は使わず、全件を展開形で書いてください。** 定義用のマッピング（_pub など）とカードの列を同じブロックに混在させないでください。
3. **「改訂カード」（ES-R01 のような仮ID）は作らず、最初から最終IDで書いてください。** ID は GD-001 から始めます。出典が取れず作らなかった番号は欠番として一覧にしてください。
4. **出典マスターの SRC 番号は3桁で、SRC-028 から採番してください**（SRC-001〜027 は第1回で使用済み）。各カードの `provenance.source_ref` に SRC 番号を入れてください。
5. `basis_tag` は使わず、`legal_basis` と `source_class` の2欄で書いてください。
6. `status` はすべて `draft`、`verifier` は `null` にしてください。`verified_sources` への昇格は、リポジトリ側で API 照合した後に行います（前回は調査側で付けた verified_sources を、照合前のため draft に戻しました）。
7. **主張文に「（要確認）」などの括弧書きを入れないでください。** 不確かな点は `uncertainty` に書いてください。
8. `curriculum` 欄は、下の第4節の番号表から選んでください。表にないものは推測せず `null` にしてください。

## 2. 内容の確認（照合で見つかった誤りの傾向）

前回の成果物を PubMed の抄録やガイドライン本文と照合したところ、次の誤りがありました。同じ傾向に注意してください。

- **二次資料から写した数値が、一次資料と違っていた。** 例：KEYNOTE-590 の5年生存率を 10.9%対3.1% としていたが、5年追跡論文の抄録では 10.6%対3.0%。数値は一次資料（抄録か本文）で確認できたものだけを書き、確認できなかったものは `uncertainty` に「二次資料経由」と明記してください。
- **ガイドラインの本文にない記述が、そのガイドラインを出典として書かれていた。** 例：ACG Barrett 2022 を出典とする「HGD の癌化率 年約7%」、Chicago 分類 v4.0 を出典とする「正常値データベース 75人→469人」は、いずれも本文に記載がありませんでした。ガイドラインを出典にするときは、その版の本文に書いてあることだけを書いてください。
- **1枚のカードに2つの論文の識別子が混在していた**（原著の PMID と追跡論文の DOI）。1枚のカードの識別子は1つの文献にそろえてください。
- PMID・PMCID は、確認できなければ空欄で構いません。DOI があれば、リポジトリ側で API により確定します。

## 3. 重複を避ける範囲

→ 第2回では、これらと同じ命題を作らないでください。NSAID・低用量アスピリン潰瘍は「予防・リスク因子」の観点で扱い、出血時の対応（UG）や特発性潰瘍（HP-019）と重ねないでください。胃 MALT リンパ腫は、除菌の位置づけ（HP-020）以外の点（病期、除菌無効例の治療など）を扱ってください。
