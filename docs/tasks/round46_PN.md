### 1-2. 作り手への追加の注意（これまでの回で見つかった点）

2つの作り手を比べた試行で、次の点が取り込み側の手間になりました。受け入れ検査でも確認します。

1. **論文の出典には、DOI と PMID を必ず書いてください。** 有名な試験（大規模 RCT など）ほど DOI・PMID は簡単に確認できます。調べても確認できなかったときだけ空欄にし、出典表の「確認経路」にその理由を書いてください。
2. **薬の名前が出るカードには、`uncertainty` に国内の承認・保険適用の確認状況を書いてください**（例：「国内承認は PMDA の添付文書で確認」「国内の適応は未確認」）。
3. **ライセンスは、Crossref の license 欄または出版社ページで CC BY と確認できたら `OPEN` にしてください。** 確認できないものは `UNKNOWN` で構いませんが、BMC・Frontiers・PLOS など CC BY の雑誌を `UNKNOWN` のままにしないでください。CC BY-NC・ND は `RESTRICTED` です。
4. **`condition.region` は全件に書いてください**（日本・米国・欧州・国際など）。日本と海外で基準や推奨が違う点（薬剤の承認と保険適用、スクリーニングの時期と方法、ガイドラインの版など）は、地域ごとに別のカードにしてください。
5. 成果物には、作成に使ったツール名・モデル名・サービス名を書かないでください。
6. **出題基準・コアカリの番号は、必ず第7節の表からそのまま写してください。表にない番号を作らないでください。** 当てはまる項目がなければ `kokushi: null` で構いません（第19回で、表にない番号を組み立てたため差し戻しになりました）。
7. **出典の重複確認は、その回の中だけでなく、前の回の納品分と出典マスター全体（`data/sources/sources.yaml`）とも照らしてください。** 既存の文献には新しい番号を付けず、既存の番号を使ってください（第18回で、前の回の出典に新しい番号を付けた例がありました）。
8. **コアカリの不変 id は、番号と同じ行から写してください**（第20回で、表の隣の行の id を写した例がありました）。出典表を出す前に、表の中に同じ DOI が2回出ていないかも確かめてください（第20・21回）。
9. **StatPearls（NCBI Bookshelf の解説書）は二次資料として扱い、原則として出典にしないでください。** 一次資料（原著論文、診療ガイドライン、系統的レビュー、公的資料）がどうしても見つからないときだけ補助的に使ってよく、その場合は `uncertainty` に「二次資料経由（StatPearls）」と書いてください（2026-10-28 の決定。受け入れ検査で件数を数えます）。

## 2. 出力形式（これまでの取り込みで実際に問題になった点）
