# 食道 v1／v2 統合：対応表の案と承認のお願い（2026-10-12、claude-code）

対象ファイル：`proposals/es_merge_map.csv`（`scripts/es_merge_map.py` が生成。UTF-8 BOM付きなので Excel でそのまま開けます）

## 1. 記入してほしい列

| 列 | 記入する行 | 書き方 |
|---|---|---|
| `approved_v1_id` | ES-R01〜R19 | 引き継ぐ v1 の ID を**1つ**（例：`ES-049`）。置換先がなければ `new`（ES-090 以降を採番します） |
| `approved_retire_v1_ids` | 全行（任意） | このカードに置き換わって廃止する v1 の ID を `;` 区切りで（例：`ES-050`）。空欄なら v1 カードはそのまま残します |

- ES-069〜089 の行（`proposed_action = keep`）は ID が v2 で確定済みなので、`approved_v1_id` は空欄のままで構いません。v1 に重複カードがあれば `approved_retire_v1_ids` に書いてください。
- `retired` にした v1 カードの `superseded_by` には、その行のカード（引き継いだ ID、または新規 ID）を記録します。
- **ES-068** は指示書どおり自動で `retired` にし、`superseded_by` に ES-069〜075、079〜081、085〜087、089 を列挙します。欠番（076〜078、082〜084、088）は作りません。

## 2. 列の意味

- `candidate_v1_ids`／`score`：候補は最大3件。スコアは「主張文の文字バイグラム Dice 係数（0〜100）＋数値・英字語の一致×0.1＋出典一致なら15」。
- `match_basis`：候補ごとの内訳。`source_ref=`・`doi=`・`pmid=`・`first_author=` は出典が一致した根拠。
- `proposed_action`：`replace`（1件を置換）／`split`（同じ出典の複数 v1 にまたがる）／`new`（置換先なし）／`keep`（ES-069〜）。
- `note`：「ES-xxx にだけある数値」は、v1 にあって v2 の主張文にない数値です。v2 で数値が更新・削除された可能性があります。
- `R_statement`／`candidate_statements`：比較用に主張文の全文を載せています。

## 4. あわせて決めてほしいこと

1. **v1 カードの provenance の扱い**：v2 の変更履歴には「上記以外の ES-001〜067 は provenance を SRC の値で置換する」とあります。ただし SRC 表の識別子もまだ API で照合していません。
   - 案A（推奨）：統合では provenance を変えず、`source_ref` の付与だけにとどめる。識別子は Phase 3 の API 照合で確定する。
   - 案B：統合時に SRC 表の識別子で上書きする。
2. **置換したカードの `created`**：v1 の値（2026-10-10）を残す想定です（v2 も同じ日付です）。
